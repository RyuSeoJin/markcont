# 🧭 워크플로우 작성 규칙

기획서의 흐름 노드 자료 · 노출 위치처럼 **넓게 펼쳐 보여야 하는 워크플로우**를 markcont에서 읽기 좋게 쓰는 기준입니다.
흐름도 문법은 [마크다운 작성 규칙](마크다운-작성-규칙.md)의 7-2장을 따르고, 여기서는 **큰 흐름에서 지킬 것**만 다룹니다.

> [!TIP]
> AI에게 워크플로우를 맡길 때는 이 문서와 작성 규칙을 함께 주고 **"이 규칙대로 흐름도와 노출 위치를 다시 써 줘"** 라고 하면 됩니다.

---

## 1️⃣ 먼저 나누기

| 기준 | 권장 |
|:---|:---|
| 한 흐름도의 노드 수 | 30개 이하. 넘으면 기능 단계별로 흐름도를 나눔 |
| 한 섹션의 노드 수 | 10개 안팎 |
| 섹션을 나누는 단위 | 사용자의 목표 하나 (열기 · 받기 · 삭제 · 닫기) |

- 코드가 `N1` · `N23` 처럼 섹션 앞부분이 없으면 **섹션 줄**로 묶습니다.
- 섹션 사이 이동은 「→ 코드」 연결자로 자동 표시됩니다. 같은 노드를 두 섹션에 두지 않습니다.

```markdown
# 우편함 열기: N1 N2
# 우편 보상 받기: N9 N8 N10 N11 N12 N13
```

---

## 2️⃣ 도형 하나에 한 가지

- **문구는 20자 안팎**으로 핵심만 씁니다. 자세한 조건과 문구는 정책 표에 두고 ID로 가리킵니다 — `보상 지급 (MAIL-P15)`.
- 화면 · 창은 앞에 종류를 붙입니다 — `[바텀시트] 우편함 노출` · `[팝업] 공통 에러` · `[토스트] 만료 안내`.
- **사용자 조작은 유저 구역의 행동 도형**, 시스템의 판단은 **조건 도형**으로 나눕니다. 조작을 선 글자로 대신하지 않습니다.
- 「판정 기준」 칸은 조건 도형에만 씁니다. 그림에는 마름모 옆에 작게 보입니다.

---

## 3️⃣ 갈래 줄이기

한 도형에서 나가는 선이 많을수록 선 · 글자가 빽빽해집니다.

| 기준 | 권장 |
|:---|:---|
| 한 도형에서 나가는 갈래 | **4개 이하**. 5개 이상이면 조건 도형을 두 단계로 나눔 |
| 선 글자(나감의 라벨) | **12자 이하** — `저장 실패` · `대상 없음` |
| 예 · 아니오 | 조건 도형에서만 |

- 선 글자가 길면 두 줄까지 감싸고, 더 길면 줄임표로 잘립니다(마우스를 올리면 전체). 긴 설명은 **도착 도형의 문구나 정책 표**로 옮깁니다.
- 갈래가 많은 도형은 높이가 늘어나 선 사이가 벌어지지만, 갈래 자체를 줄이는 쪽이 훨씬 읽기 쉽습니다.

````markdown example
```flow
A1 | 시스템 | 공통 처리 | 지급 계산 · 저장 | → A2 · 성공 / → A3 · 실패 / → A4 · 대상 없음
A2 | 시스템 | 출력 | [팝업] 보상 수령 | —
A3 | 시스템 | 출력 | [팝업] 공통 에러 | —
A4 | 시스템 | 출력 | [토스트] 받을 보상 없음 | —
```
````

---

## 4️⃣ 긴 선 대신 연결자

| 경우 | markcont가 그리는 것 |
|:---|:---|
| 다른 섹션으로 감 | 「→ 코드」 연결자 |
| 두 열 이상 되돌아감 | 「↩ 코드」 연결자 |
| 앞으로 멀리 건너가 그림을 가로지름 | 「→ 코드」 연결자 (자동) |
| 정해진 도형으로 되돌아가는 지점 | `반복` 도형(원) |

- 흐름도에 `긴 선 끊기` 줄을 쓰면 두 열 이상 건너가는 선을 모두 끊고, `긴 선 잇기` 줄을 쓰면 끊지 않습니다.
- 같은 화면으로 돌아가는 선이 많으면 연결자가 여러 개 생깁니다. 돌아가는 곳이 같다면 하나의 공통 처리 도형으로 모은 뒤 돌아가게 합니다.

---

## 5️⃣ 크게 볼 때

- 섹션이 여럿이고 옆으로 너무 길면 **섹션이 위아래로 쌓여** 보입니다. 섹션마다 유저 · 시스템 구역이 따로 그려집니다.
- 다이어그램 오른쪽 위 **⤢** 로 크게 보면 휠 · 두 손가락으로 확대 · 축소, 끌어서 옮기기, 「화면에 맞추기」를 할 수 있습니다.

---

## 6️⃣ 노출 위치

들여 쓴 목록을 ```` ```노출 ```` 코드 블록에 넣으면 **📍 위치 → 🚪 진입점 → 진입하면 노출** 나무로 보입니다.

| 쓰는 법 | 보이는 것 |
|:---|:---|
| 들여 쓴 줄 | 위 줄 안에 놓이거나 위 줄에서 열리는 UI |
| `🚪 이름` · `진입: 이름` · 끝에 `(들어오는 곳: …)` | **진입점** (초록 상자). 그 위쪽 줄은 📍 위치, 아래쪽은 「진입하면 노출」 묶음 |
| `조작 → 결과` | 조작은 흐리게, 결과는 굵게 |
| `[버튼]` | 버튼 모양 |
| 끝의 `(설명)` | 작은 회색 설명 |
| 이름에 바텀시트 · 팝업 · 토스트 · 화면 · 탭 · 레드닷 | 종류 아이콘과 왼쪽 색 |

````markdown example
```노출
- 메인 화면
  - 홈 탭
    - 내비게이션 바 [우편함] (들어오는 곳: 진입 동작 표)
      - 레드닷 (보상을 받을 수 있는 우편이 있을 때)
      - 우편함 바텀시트
        - 우편 카드
          - 카드 영역 누르기 → 우편 상세 바텀시트
          - [받기]
            - 지급 성공 → 보상 수령 팝업
            - 받을 우편 없음 → 토스트
        - [삭제] → 삭제 확인 팝업
```
````

- 진입점은 **사용자가 그 기능으로 들어오는 자리**(버튼 · 메뉴)에 표시합니다. 진입점이 여러 곳이면 각각 표시합니다.
- 다른 뷰어용으로 저장하면 일반 들여 쓴 목록으로 바뀝니다.

---

## 7️⃣ 데이터 정의

구현에 필요한 데이터는 「구현 필수 정보」 표에 한 칸으로 몰아 쓰지 말고, ```` ```데이터 ```` 블록으로 **데이터 하나 = 카드 하나, 필드 하나 = 줄 하나**로 씁니다. 쓰는 법은 [마크다운 작성 규칙](마크다운-작성-규칙.md) 7-2장의 「데이터 정의」를 보세요.

- 「구현 필수 정보」 표는 **정해야 할 것(결정 목록)**으로 남기고, 데이터 정의는 그 아래 따로 둡니다.
- 필드 이름은 화면 · 정책에서 부르는 이름과 같게 씁니다 — `우편 제목` · `우편 만료 일시`.
- 다른 데이터를 담는 필드는 형식에 그 데이터 이름을 씁니다 — `보상 목록`. 카드 사이에 연결선이 생깁니다.
- 정해지지 않은 필드는 상태 칸에 `미결` 을 씁니다.
